# ADR-002：注册按插件暂存，成功后原子发布

状态：CLI 重构第 1 步已采用。配置加载与 manifest 校验尚未接入。

## 背景

一个插件可以同时贡献图形、命令、树标签和属性处理器。如果每次 register 都立即修改全局注册表，后续重复注册或 activate 异常会留下部分能力。异步激活还可能使另一个插件基于过期状态提交，覆盖已经成功的注册。

## 决策

- PluginRegistry 串行调用插件的 activate，每次创建 PluginRegistration，使用当前发布版本作为暂存起点。激活返回成功且暂存区未发生注册错误时，替换一次 PluginContributions 引用发布四类注册。
- ExtensionRegistry 的 with 返回新表，保留原实例、原顺序与原贡献对象身份；values 返回冻结数组。相同类别名称唯一，跨类别允许同名；名称不能为空或含空白字符。注册时验证该类别的必需方法存在。
- PluginContext 是冻结的四方法门面，不包含发布、注销、会话、历史、文档或树写接口。插件得不到 PluginRegistration 本身。成功和失败均关闭上下文，后续调用报错。
- 注册异常使整次激活永久失败，即使插件捕获了异常也不能提交其他暂存项。已成功插件不受影响；失败 Promise 交给调用者，内部队列继续处理后续激活。
- 注册错误保留 PluginRegistrationError；其他激活异常封装为 PluginActivationError 并保留 cause。应用层不输出终端文本，不添加 error: 前缀。将来由装配适配层报告错误并继续启动。
- 事务保证注册成员关系的原子性，不声称能撤销插件在其自身对象或注册上下文之外执行的副作用。不冻结有状态插件实例；实例的注册名和契约方法须保持稳定。

## 取舍与后续边界

与先写全局表、失败后逐项删除相比，暂存版本不需要猜测补偿顺序，也不会把部分注册暴露给读者。代价是注册期间复制 Map，激活按顺序等待；当前插件规模较小，选择简单、可验证的失败语义。

保留既有 Command 执行接口，另用 CommandContribution 描述发现、帮助与构造。ShapeProvider 本步只承载类型化创建规格入口，不预先固定内部树、候选子树和 SVG 编解码接口；这些在第 3—5 步迁移实际链路时完善。AttributeHandler 使用只读快照匹配、受限上下文准备 ChangeSet，并提供结果读取能力；实际 set 选择、冲突与事务契约仍在第 6 步实现和记录。TreeDecorator 复用查询快照，树排版及 dirty 生命周期在后续接入。

没有提前实现 package.json 读取、配置解析、动态 import、manifest 匹配或 options 协议。第 8 步的两种装配须复用本注册事务，并在原子发布前增加清单校验；本 ADR 不把该后续校验记为已完成。
