# Phase 1 开发阶段

本计划按 `doc/README.md` 的分层架构和 TDD 流程推进。每个阶段先写失败测试，再实现、重构并运行全量测试和类型检查；失败命令必须保持全部状态不变。

## TDD 工作流程

每个功能按以下循环开发：

1. **明确行为**：从需求中选一个可观察的行为，确定输入、成功结果、错误输出和状态变化。
2. **先写测试**：按 Arrange -> Act -> Assert 编写测试，测试接口以使用者视角设计。
3. **确认失败**：运行目标测试，确认它因功能尚未实现而失败，而不是测试或环境错误。
4. **最小实现**：只实现让当前测试通过所需的代码，同时遵守模块职责和依赖方向。
5. **回归验证**：运行目标测试、全量测试和类型检查，确认原功能未被破坏。
6. **重构**：在测试全绿的前提下消除重复、改善封装和对象职责，重构后再次运行全部检查。
7. **记录证据**：保存真实测试命令和结果；测试没有通过前，不把功能写入完成记录。

不同层级的测试重点：

- **领域层**：图形几何、属性、id、父子关系、顺序、防环和局部变更记录。
- **命令层**：命令调用后的状态变化，以及 undo/redo 是否精确恢复。
- **执行器与历史层**：命令顺序、历史入栈、redo 清空、屏障和失败不变。
- **IO 层**：使用替身和临时目录验证读取、保存、失败清理及 round-trip。
- **CLI 与端到端**：分词、输出格式，以及从 REPL 到领域模型的完整操作链。

测试必须独立、无副作用且可快速重复运行。修复 bug 时先添加能复现问题的失败测试；复杂编辑除输出外，还要比较父级、顺序、属性存在性、几何和 id 索引。生产历史仍只保存局部 `ChangeSet`，不得用测试快照替代撤销设计。

## 阶段 1：工程基线与需求固化（已完成）

**要做什么**

- 建立 Node.js、TypeScript 严格模式、测试框架和基础检查脚本。
- 创建 `cli`、`application`、`domain`、`infrastructure`、`bootstrap` 和 `tests` 目录。
- 明确跨父级 `group`、外部 SVG 的不支持内容、`text` 缩放、`save` 默认路径等边界。
- 把需求转成领域、命令、执行器、IO 和 CLI 的测试清单。

**实现功能**

- 可编译、可运行、可测试的 TypeScript 工程骨架。
- 本阶段范围内不再存在未记录的行为约定。

## 阶段 2：最小纵向链路

**要做什么**

- 先打通 `init -> create rect -> tree -> save`。
- 建立最小 `EditorSession`、`CommandDispatcher`、`CommandExecutor`、`CommandHistory`、`DocumentService` 和 `SvgDocument`。
- 建立 `Command`、`ShapeFactory`、`DocumentStore`、查询访问者和基础 REPL。

**实现功能**

- 可以初始化画布、创建矩形、查看结构并保存 SVG。
- 验证 CLI、应用层、领域层和 IO 之间的依赖注入与调用方向。

## 阶段 3：领域模型与 Composite

**要做什么**

- 实现 `Shape`、`Group` 和六种叶子图形：`rect`、`circle`、`ellipse`、`line`、`text`、`g`。
- 实现 `SvgDocument` 的唯一 id 索引、父子关系、同级顺序和图形查找。
- 实现叶子与容器统一的 `move`、`scale`、`set`、`delete`。
- 实现 `ShapeVisitor`，统一进入、遍历、离开和子树跳过语义。

**实现功能**

- 六种图形的创建、样式和几何属性。
- 容器递归操作、防环、子树删除和根级容器约束。
- 查询和 SVG 输出共用的树遍历基础。

## 阶段 4：结构编辑与局部变更记录

**要做什么**

- 实现 `create ... in`、`group`、`ungroup`、`addto`、`front`、`back`。
- 为 create、delete、move、scale、set 和结构调整记录精确的局部 `ChangeSet`。
- 保存旧值、新值、属性是否存在、原父级、目标父级和原/新位置。
- 先完成候选状态与全部校验，再同步提交文档变化。

**实现功能**

- 完整的有序树编辑能力。
- 可精确恢复每个编辑动作，不复制整份文档。
- 多节点操作失败时不会出现部分修改。

## 阶段 5：Command、执行器与撤销重做

**要做什么**

- 实现薄命令类、命令结果和 `CommandDescriptor`。
- 由 `CommandDispatcher` 集中按名称创建命令，`help` 与描述符同源。
- 由 `CommandExecutor` 串行执行命令并协调历史。
- 实现 undo、redo、redo 清空、查询不入栈和文档命令历史屏障。

**实现功能**

- 全部编辑命令均可执行、撤销和重做。
- 每条编辑命令是一个撤销单元。
- 失败命令不改变文档、默认路径、历史栈或屏障。

## 阶段 6：文档操作与 SVG IO

**要做什么**

- 实现 `DocumentService` 的 `init`、`read`、`save` 和 `canvas`。
- 实现 `SvgReader`、`SvgWriteVisitor`、`SvgDocumentStore` 和 `DocumentStore` 契约。
- 读取时先构造并校验候选文档，成功后再替换当前会话。
- 保存时先写同目录临时文件，成功后再替换目标文件。
- 实现缺 id 自动编号与警告、命名空间、文本和属性转义。

**实现功能**

- SVG 文件读取、保存和模型语义 round-trip。
- 默认路径、显式路径和画布尺寸调整。
- 读写失败时保留原文档和原路径。

## 阶段 7：查询、CLI 与启动装配

**要做什么**

- 实现只读查询模型和 `DocumentViewVisitor`。
- 实现 `tree`、`show` 和完整 `help`。
- 实现通用分词、双引号参数、整行注释、浮点数和颜色参数处理。
- 实现 REPL、输出格式化和 `bootstrap/main` 依赖装配。

**实现功能**

- 所有需求命令均可从 `svg>` REPL 调用。
- 树结构、属性明细和错误输出符合约定。
- CLI 只负责输入输出和排版，不承载领域逻辑。

- 补齐领域、命令、执行器、IO 和 CLI 的单元、集成及端到端测试。
- 回放需求典型会话和流程图案例 A。
- 保存 SVG 后用浏览器检查几何、颜色、层级和文字。
- 检查一类一文件、字段封装、两处分派、依赖方向和历史实现。
- 填写实际测试证据、一致性自查和 `doc/WORK_MEMORY.md`。

**实现功能**

- 完整、可回放的 Phase 1 CLI SVG 编辑器。
- 可复现的验收证据和实际质量结论。
- 最终验收通过后，再创建并推送 `final` tag。
